# Language behavior

JanAwaaz uses the shared `LanguageProvider` and typed dictionaries in
`lib/i18n/dictionaries.ts`. The current locale preference order is:

1. An explicit manual selection (`janaawaaz_lang_source=manual`)
2. The signed-in account preference
3. The saved browser preference
4. The browser's language
5. English

Manual selection is stored in local storage and the `ja_lang` cookie. The
provider ignores a pending account-language response if the user changes the
language while that request is in flight. Login preserves a manual selection.
Urdu sets the document direction to right-to-left.

The supported locales are English (`en`), Hindi (`hi`), Hinglish (`hi-Latn`),
Bengali (`bn`), Telugu (`te`), Marathi (`mr`), Tamil (`ta`), Gujarati (`gu`),
Kannada (`kn`), Malayalam (`ml`), Punjabi (`pa`), Odia (`or`), Assamese
(`as`), and Urdu (`ur`). Hinglish uses Roman Hindi copy.

Run `npm run i18n:check` to compare dictionary keys, values, and duplicate
object properties across the supported locales. Run `npm run test:i18n` for
preference-order, script, draft, AI response, and dictionary-shape tests.

The dictionary checker validates registered catalog messages. It does not
automatically detect every hard-coded JSX string or translate user-submitted
content, third-party map labels, or official responses.
